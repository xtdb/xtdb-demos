The initial report used just four reviews. Later reviews can reveal missed defects or reverse earlier judgements. XTDB can still reproduce the earlier report using the data available when it was saved.

How XTDB keeps these views consistent

Part records and model predictions are retained. A review describes the part’s condition from its production time; system time records when that assessment entered the database. Revising a review preserves the earlier version.

Current analytics and historical reports use the same SQL. The saved system-time snapshot applies to parts, predictions and reviews together. Report values are recalculated from that history, not loaded from stored totals.

This demo covers inspection, review and reporting. A missed defect on an originally released part requires operational follow-up; these review buttons do not change stock disposition. All parts in this simulation remain in stock.
